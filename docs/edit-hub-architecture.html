Edit Hub

How Edit Hub works

A local app where you talk to a Director, and a crew of Claude Code agents turns a raw recording into a finished, posted video. Everything runs on your computer with your own Claude plan. This page maps every part, so you can see what to improve.

The big picture

Three layers. The browser page is only a window. The Edit Hub server (Node, on 127.0.0.1) owns the files, the queue and the Director. Claude Code does all the thinking and editing, as one Director process with crew agents under it.

The stack

Server

TypeScript on Node 22.13+, with no build step: Node strips the types as each file loads (server/ts.js), and the installer stays plain JavaScript so it runs on any Node 22. No framework. One loopback HTTP server with Server-Sent Events for live updates. It refuses any page that is not its own.

Page

TypeScript modules the server hands to the browser with their types removed, and CSS tokens. One theme file sets every colour and font; each page is a function that draws into the main area.

Agents

Claude Code: the Director as claude -p --input-format stream-json, crew agents as its subagents (Sonnet unless an agent names a model), skills as Markdown folders.

Media

ffmpeg for cutting, mixing and encoding; faster-whisper (Python, GPU when there is one) for transcripts and the microphone; films are HTML (HyperFrames) rendered to MP4.

Tools for agents

An MCP server (hub_live, hub_notes, hub_render, hub_project…) so agents open previews, read your notes and queue renders.

Terminal

node-pty runs an interactive Claude Code for the "Director in a terminal" view, the only place Code Mode works.

The standard job: raw recording in, finished video out

  Ed->>Ed: clean cut, edit in your style, captions, sound, own check
  Ed->>Hub: hub_live (live preview, no render)
  Dir-->>You: ready to review in Projects
  You->>Hub: notes on frames, then Render
  Hub->>Ed: your notes (the editor still has the film's context)
  You->>Dir: schedule it Friday 18:00
  Dir->>Dir: post from your Chrome (social-uploader)

How the crew learns from your fixes

  1. You correct something in the chat or as a note on a frame in the review page.
  2. The agent that made it fixes it and adds one dated line under "Standing notes" in its own file: what to do from now on, and why.
  3. Look fixes go to the style skill too ("Notes from the user"), so every agent using that style gets them.
  4. Every later job starts by reading those notes, so you never repeat yourself. Agents with memory: project also keep their own memory folder.

yours

The workspace

films/ (one folder per film), inbox/ (dropped videos), outputs/ (renders), crew/ (your Director and agents).

yours

The crew folder

CLAUDE.md (the Director's prompt), channel.md, brand.md, .claude/agents, .claude/skills (your style skill lives here).

Claude Code

Conversation logs

~/.claude/projects/<crew folder>: every conversation and agent. Edit Hub reads them for history, costs and agent status.

What to improve next

The honest list of weak spots, with where to look.

by design

A small crew

Two agents (editor, writer) so nothing is lost between hand-offs and no tokens go to agents re-reading the same files. A fresh-eyes reviewer is worth adding only when you want one; ask the Director.

quality

Your style is a first draft

The Director writes the style skill from a few clicks. The real look comes from your fixes over the first videos; a library of tested style starters would help.

fragile

Uploading drives web pages

The uploader clicks YouTube's and Meta's own pages. When they change their layout, it breaks until its skill is updated. TikTok does not work.

cost

Every edit uses your Claude plan

Crew agents run on Sonnet by default and every reply shows its cost, but a long edit with many fix rounds still adds up. The edit-plan step and fix limits help.

platforms

Windows first

macOS and Linux paths exist and have tests, but they have not run on real machines yet.

optional skills

Some skills cannot ship

onetake (non-commercial licence), real-sfx (sound licences unknown) and others are not bundled: users install them themselves.
